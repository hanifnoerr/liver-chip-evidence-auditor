User guide

Review, import and export

How to use the interface, prepare a compatible CSV and reproduce the analysis locally.

Review an example

  1. Select a compound on the Review page.
  2. Read the estimated 50% crossing and whether evidence changes affect it. A censored result has no finite crossing estimate.
  3. Read the source-specific action cards. Each names the affected evidence, explains its effect and offers a conditional next step.
  4. Use “Locate measurements” or “View calculations” to highlight supporting records and scenarios. Unchanged hypothetical probes are shown when needed.
  5. Inspect unassessed experimental evidence or expand the full checklist. “Not assessed” means the necessary evidence has not been verified.
  6. Select “Choose what to do next” to set your goal and resources. Choose rules or the experimental local language model at the top of that page.
  7. Read “Do this now” and “Fits your resources.” Links under supporting readings return to Review and highlight the exact source record. Reporting includes the measured dose range, sensitivity findings and unassessed evidence.
  8. Export the evidence report or action plan as JSON.

Switching to a published comparator opens its case; it does not create a matched-chip or side-by-side comparison.

How evidence cards are created

Rules create evidence cards from source records and sensitivity scenarios. The cards identify influential readings, missing measurements, dose dependence, loss of bracketing coverage and disagreements between curves.

Reading and whole-dose concerns at the same dose share a card when they overlap. Missing measurements remain a separate concern even when none of the tested replacements changes the conclusion. Removing a boundary dose may remove bracketing coverage without showing that its measurements are erroneous.

Cards follow a fixed review order, not a calibrated ranking or optimal experimental design. Original measurements remain included. Dose extension is conditional on needing a finite crossing and laboratory suitability; a censored result can be retained.

Follow an action through to its outcome

  1. Run Next action, then use its action-specific button to open “Record what happened.” The action, original audit, request and resources are retained separately from the current Review data.
  2. Inspect the linked source records. “Return to saved action” takes you back to the outcome form. The plan and text draft survive navigation and reload within this browser tab; files must be selected again.
  3. Record an action-specific outcome and note. Completed reviews and decisions need a source or laboratory-record reference. Notes alone leave measurements, computed checks and the numerical conclusion unchanged.
  4. For a documented correction, recovered original or new actual observation, select the evidence-update outcome and upload the complete compatible CSV. Keep baseline IDs; retain observed readings. Document sampling and normalisation compatibility and any experimental differences. This account is researcher-reported, not independently verified.
  5. The local server re-audits both versions. Compare their conclusions, measured ranges, observed/missing counts, changed source records, individual computed checks and remaining unassessed evidence. A changed conclusion or fewer triggered checks does not prove experimental validity.
  6. Open the updated Review, export the complete action/outcome record, or choose another action from the updated evidence. Each action retains one reassessment; later changes start a new plan. Case history exports retain earlier records.

The browser session is temporary. Export before closing the tab. If storage is unavailable, the app prompts you to export rather than claiming that work was retained. A rejected CSV leaves the original plan and recorded outcomes intact. Reset examples restores the example measurements; it does not erase exported or separately retained action records.

Import your measurements

Use the example CSV's column names. The local server analyses albumin rows separately for each compound. The downloadable example also contains other endpoints; those rows are ignored by this release.

Preserve all example column headers, including the additional source-file, source-DOI, source-row and missing-reason fields. Duplicate IDs, incompatible units and derived summaries block fitting. At least two observed dose conditions are needed. Do not turn missing measurements into zero.

An imported CSV is processed by the local server. Its rows are not uploaded to an external service by this implementation. The selected case and imported analyses stay in this browser tab's session storage while you visit the other pages or refresh. “Reset examples” clears imported analyses and restores the included cases.

Run locally and reproduce results

The saved HTML pages work without Python for exploring the included results. New CSV fitting requires the local analysis server.

Install the project environment

conda env create -f environment.yml
conda activate ai4s-liver-auditor

Regenerate and check the results

python run_auditor.py
python check_auditor.py

Enable CSV import

python demo.py

Open the local Review page. Use “Import CSV” to fit your file. Opening the HTML as a file displays saved examples and disables new fitting.

Run the model planner

Extract the checkpoint into the project root and create the environment from small_model/environment.yml. Activate ai4s-liver-slm, then run:

python demo.py --model small_model/checkpoints/smollm2-135m-policy --threads 4 --port 8767

Open the model-enabled planner and choose Small language model · experimental. Full instructions cover installation and reproduction.

The adapted model matches 92.6% of test policy labels before guards and 99.2% after guards, versus 100% for rules, and fails the per-class engineering gate. These are authored heuristic-policy labels, not biological validation. Numerical evidence remains supplied by Python. Named edge hardware and quantisation are untested.

Understand the export

The evidence report is a JSON file for inspecting or reusing the complete case results. It contains the original readings, source references, fitted curves, finite sensitivity scenarios, checklist statuses and suggested next steps. Action-planner exports also retain the active engine, request, resources, raw choice and delivered choice.

Influence is a temporary recalculation, not an automatic exclusion. Passes apply to individual checks; they do not certify assay validity or drug safety.
